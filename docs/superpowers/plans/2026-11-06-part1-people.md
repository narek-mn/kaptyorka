# Part 1: People (kaptyorka 0.2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-person accounts, device tokens and invites, GitHub-style roles on projects and machines, private groups with doors and knocks, access requests, attachments, an audit log, retention, and a per-person web page, on top of kaptyorka 0.1.9, with a hands-off migration.

**Architecture:** The hub keeps one SQLite store (`store.py`) and one Starlette/MCP app (`hub.py`). Part 1 adds tables and a `Principal` resolved from the bearer token on every request, threads the principal through every store method that decides visibility, and adds MCP tools and admin routes. The bridge and shim change only where they must carry new facts (host, OS user), handle two new poll item kinds (`rekey`), and move attachments. The page gains a login and admin tabs.

**Tech Stack:** Python 3.10+, `mcp` SDK (Starlette, uvicorn come with it), sqlite3, hmac/hashlib, pytest. Plain HTML/JS page.

**Spec:** `docs/superpowers/specs/2026-11-06-team-brain-design.md`, section "Part 1: People (0.2)" plus "Words", "Constraints", "What stays the same", "Testing", "My calls".

## Global Constraints

- Python 3.10 floor: no `match`, no `X | Y` in runtime annotations, no `tomllib` in `src/`.
- Dependencies stay `mcp>=2.3,<3`; no new dependency without a reason written in `pyproject.toml` as a comment.
- Tests never call real agent tools except under `-m slow`.
- A 0.1.9 bridge or shim keeps working against this hub: old routes and old tool shapes stay; new fields are added, none removed; the old shared token keeps working as the `legacy` device.
- LAN or VPN only, plain HTTP; `/`, `GET /i/<code>`, `POST /i/<code>` are the only unauthenticated routes; `POST /i/<code>` and failed token checks are rate-limited to 10 failures a minute per client address.
- The page stays one HTML file, dark, no build step; same look as 0.1.8.
- No team-specific names (people, projects, machines) in code, tests, docs or fixtures: use `alice`, `bob`, `proj-a`, `box-1`.
- Secrets never in git: tokens live in `~/.kaptyorka/config.json` (0600) and hashed in the store.
- Commit after each task; never push.
- Version bumps touch four places: `pyproject.toml`, `src/kaptyorka/__init__.py`, `tests/test_cli.py`, `CHANGELOG.md`.

## Review Focus

1. A request with a revoked device token must get 401 and never a 500, and the revoked device's running sessions must drop from `who()` within the presence window. Test in Task 2.
2. Two people with the same project folder name on different machines: `who()` must not merge them into one project and `notes_*` with that project must resolve per registered project, not per folder. Test in Task 5.
3. A knock to a person with no online session must be held, shown on the page, and delivered to that person's next session, not to the admin and not lost. Test in Task 6.
4. An upload of exactly 5 MB passes, 5 MB + 1 byte is refused with the reason; a file with a path-traversal name (`../x`) is stored under its id and the name is only metadata. Test in Task 8.
5. The legacy token after the admin reassigns a machine: a request from that machine name must be attributed to the new person immediately, and after the rekey order is consumed the old token from that machine still works until the bridge restarts. Test in Task 10.

### Task 2: Principals and auth middleware

**Files:**
- Create: `src/kaptyorka/auth.py`
- Modify: `src/kaptyorka/store.py`, `src/kaptyorka/hub.py` (replace `BearerAuth`), `src/kaptyorka/cli.py` (`_serve` passes `legacy_token=token`)
- Test: `tests/test_auth.py`

**Interfaces:**
- Produces in `store.py`:
  ```python
  @dataclass
  class Principal:
      person_id: int; person_name: str; role: str       # admin | member | manager
      device_id: int; device_name: str; shared: bool; legacy: bool
      def is_admin(self) -> bool
  def authenticate(self, token: str, machine: Optional[str] = None) -> Optional[Principal]
  ```
  Returns None for unknown or revoked tokens. For the legacy device, `machine` (the 0.1 machine name from the identity header or heartbeat body) is consulted: if `settings` holds `legacy:<machine>` = `<person_id>` (set by Task 10), the principal is that person, device id of the legacy row, `legacy=True`. Updates `devices.last_used`.
- Produces in `auth.py`:
  ```python
  class RateLimiter:  # (limit=10, window_s=60)
      def hit(self, addr: str) -> bool   # True when still allowed; records a failure
  class Auth:  # ASGI middleware: Auth(app, store, open_paths=("/",), open_prefixes=("/i/",))
  ```
  Unauthenticated routes pass through. Everything else: resolve the bearer token with `store.authenticate(token, machine=<X-Kaptyorka-Machine header, unquoted>)`; on None → 401 (HTTP) / 1008 (WebSocket) and `limiter.hit(addr)`; when the limiter says no → 429 before any lookup. The principal is put in `scope["state"]["principal"]`.
- Produces in `hub.py`: `def principal_of(headers: Mapping) -> Principal` used by tools (the MCP `Context.headers` carry `authorization`); `identify()` sets `person_id`, `host`, `os_user` on the agent row via `store.seen(..., principal=...)`.

  def may_message(self, sender_key: str, target_row) -> bool  # same person, admin sender, or open door covering (sender_key,target_key) or (sender_person,target_person group)
